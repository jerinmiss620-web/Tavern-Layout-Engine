## 下载校验与行为边界

- GitHub Raw、jsDelivr、Fastly jsDelivr、TestingCF jsDelivr 提供多线路回退。源地址必须匹配指定仓库、固定提交 SHA 和包文件路径。
- 安装前同时检查 UTF-8 文件长度、SHA-256、JSON 格式、`type: script`、脚本 UUID 和名称；任一检查失败则不导入。
- 通过酒馆助手全局脚本管理 API `getScriptTrees({type:'global'})` 和 `updateScriptTreesWith(...,{type:'global'})` 操作，不替换整棵全局脚本树；相同 UUID、同名冲突时停止自动安装。
- 若当前宿主没有可用脚本管理 API，显示不可用，不通过模拟点击酒馆 UI 绕过限制。
- 停用/卸载不主动删除用户的原生图库、主题 CSS、本地字体数据或绑定数据。需要手动清理数据时，应使用原脚本提供的管理功能。
- 实际停用或卸载后建议刷新酒馆确认执行状态。TLE Dev6 不会自动加入正式版更新通道。

## 实验测试步骤

1. 备份当前酒馆助手脚本列表。停用旧 TLE Dev5、独立 Core 与正式版 Bootstrap/Loader，仅运行一个 TLE 实例。
2. 导入 `TLE-optional-dev6-import.json`，在酒馆助手中**手动启用**，然后刷新酒馆。
3. 打开 TLE →「可选功能包」确认出现两个卡片；点各自的「··· 更多」验证完整介绍与实际入口。
4. 已安装相同 UUID 的脚本：检查「已安装/启用/停用」状态；未安装时测试安装并启用。确认目标实际出现在酒馆助手全局脚本列表，没有重复导入或覆盖其他脚本。
5. 覆盖侠：从**底栏扩展菜单**打开。测试「实时预览 → 取消预览」「实时使用 → 取消使用」的双态按钮，检查写入 CSS 独立操作与刷新后的常驻状态。
6. iPhone TT：检查字体比例能否读取、是否可以真正修改原生设置及刷新保存。TT 备用模块通道尚待实机验证，失败时应只读显示而不是伪保存。
7. 检验停用/卸载、再次启用、已有脚本的重复检测，以及不影响其他脚本。结束后停用 Dev6，再恢复正式 TLE Bootstrap/Loader。
