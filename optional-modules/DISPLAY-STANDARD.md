# TLE 可选功能包 · 统一展示规范（v1）

本规范从 **TLE Core v0.3.213** 起执行，后续所有独立可选脚本都必须遵循。不把可选包描述为 TLE 的内置功能，也不把安装/启用状态误写成已在运行。

## 卡片固定结构

按顺序显示，两个或更多功能包不允许自行增减字段或换位：

1. **功能名称**：与正式功能名对应；右侧统一「··· 更多」，始终有可见文字/符号，不能只依靠图标字体。
2. **简短功能介绍**：具体能力和控制对象，优先使用用户认识的词；建议 4–6 项，用「／」分隔，不堆叠抽象词。
3. **版本与作者**：固定格式「版本：vX · 作者：XXX」，均与该脚本真实署名和 `manifest.json` 一致。
4. **实际操作入口**：固定格式「入口：宿主位置 → 菜单 → 按钮名称」，必须具体到操作路径；不以「进入 TLE 面板操作」代替独立脚本入口。
5. **安装状态和操作按钮**：按当前状态显示安装、启用、停用、卸载、刷新；交互不因包而更改。

卡片统一复用 `OPTIONAL_DISPLAY` 配置与 `optionalCardMarkup(kind)` 渲染器，不在模板里为各功能包手写散落的不同布局。手机端自动换行，不用固定宽度硬挤，仍沿用原生主题控件。

## 「··· 更多」弹窗固定结构

每个功能包均必须包含下列内容，顺序统一：

1. **名称和用途**：一句话明确它解决什么问题。
2. **版本与作者**：与卡片完全一致。
3. **入口**：与卡片完全一致，不允许只写「请打开对应界面」。
4. **主要功能**：以具体功能分组逐项介绍；功能多的脚本必须写全，不能以「布局优化」代替气泡居中、行高、字间距、滚动条宽度等具体功能。
5. **使用方法**：按实际点击顺序编号，包括首次安装、打开入口和核心操作。
6. **注意事项**：写清数据保存、设备差异、宿主限制、停用/卸载会保留什么。

弹窗统一复用 `optionalDetailsRender(kind, trigger)`，沿用 TLE 已有滚动弹窗结构。内容不能为了减少字数而删去重要功能；详细文字只放弹窗，不把整段塞进卡片。

## 发布检查

- 必填字段：`name`、`summary`、`version`、`author`、`entry`、`intro`、`features`、`steps`、`notes`。
- 卡片三行小字按「简介、版本/作者、入口」固定排序；两包使用相同动作按钮列表。
- `manifest.json` 的 `description`、`author`、`entry_location`、`version` 应与 UI 配置一致。
- `tests/tle-optional-presentation.test.mjs` 必须通过；原 Core 自动更新及功能包签名校验不变。
- 正式 Core 源码目录不可覆盖；使用新版本号、更新安装包、变更日志和固定 Commit 清单，并跑完整 CI。
