# Core v0.3.261 TEST · 配套侠恢复上次聊天时自动还原方案

- **识别宿主启动：** 区分完整宿主页面启动与同一页面内的 TLE Core 更新/重新启用。TT 或 ST 在页面启动时恢复上次聊天，即使角色与聊天内容已在 TLE 注册事件监听器之前加载，也会识别当前角色并应用其默认配套方案。
- **保留初始化保护：** 同一页面内更新、热重载或重新启用 TLE，只记录当前角色基线，不重复应用默认方案，不覆盖用户刚刚手动调整的模型、预设、推理格式、全局世界书或 UI 主题。
- **不依赖补发角色切换：** 不伪造 `CHAT_CHANGED`，也不要求用户重新打开角色；通过宿主 Window 生命周期标记判断首次页面启动。页面内标记按窗口隔离，不写入 localStorage，不影响其他标签页。
- **延迟恢复兜底：** 若宿主启动时角色上下文尚未就绪，最多等待 15 秒并以 500ms 间隔有限重试；正常的 `CHAT_CHANGED / CHAT_LOADED` 事件仍然优先工作。群聊不关联单角色方案。
- **日夜与手动覆盖：** 页面完整启动时优先应用当前日夜时段方案；手动覆盖尚未到期时继续保留手动方案。真正切换角色时仍按该角色默认方案执行；没有匹配默认方案时不改动现有配置。
- **配置应用引擎不变：** 全局世界书仍按完整清单同步；UI 主题、预设、模型等继续逐项应用。缺项逐项报告，其余可用项目继续应用。
- 不修改正式 Stable Core、Loader Runtime、Bootstrap；仅更新开发分支测试通道。

## 验收重点

1. TT 开启「自动加载上次聊天」，完整退出并重新进入 TT；确认恢复上次角色后，即使没有再次打开角色或手动切换，也会自动应用该角色默认方案。
2. 确认恢复方案中的全局世界书选择与保存清单完全一致，UI 主题也切换到方案绑定主题。
3. 在同一页面内更新或重新初始化 TLE Core，确认不会再次应用默认方案，也不会覆盖当前手动配置。
4. 同一页面禁用后重新启用 TLE，确认不会被误判为新的宿主页面启动。
5. 真正切换到另一角色，确认仍应用另一角色的默认方案；没有默认方案的角色不改变当前配置。
6. 启用日夜定时并分别测试当前时段、跨时段恢复及手动覆盖到期行为。
7. 在 ST 与 TT 分别检查；自动化测试通过不代替真实宿主验收。
