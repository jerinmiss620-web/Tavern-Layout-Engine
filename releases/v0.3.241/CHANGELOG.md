# TLE v0.3.241 — Test

## 配套侠初始化不再重放角色默认方案
- Core 初始化时读取当前角色并建立运行状态基线，不再把当前角色伪装成一次新角色切换。
- 加载、更新、重载 TLE 不会自动应用当前角色的默认配套方案，也不会覆盖用户当前正在使用的 UI 主题、预设、模型或推理格式。
- 真正发生角色切换时，仍按该角色的默认方案自动应用；无默认方案时保留当前配置。
- 手动应用与生成期间的待应用队列、角色切换取消机制保持不变。

## 日夜定时与手动覆盖保持
- 为每个角色持久化最近处理的日夜时段令牌；首次升级时只把当前时段记录为基线，不在升级时重放旧定时方案；后续普通刷新不会重复应用同一时段方案。
- 若 v0.3.241 已建立时段基线后，页面休眠或关闭期间跨过日夜边界，重新加载后会识别令牌变化，并补应用当前时段方案一次。
- 修改日夜定时规则时清除该角色旧令牌，使新规则立即按当前时段生效。
- 手动方案在当前时段内的优先权继续保留，到下一次日夜边界后再恢复自动方案。
- 跨午夜时间计算、定时器重校准、页面恢复监听均保留。

## 不变项目
- 配套方案保存、编辑、复制、覆盖、删除、设为默认与手动应用流程不变。
- 连接配置、接口来源、模型、预设、推理格式、UI 主题的逐项读取和应用流程不变。
- 部分可用项目继续应用；不可用项目逐项跳过，并明确报告 API 未连接、模型列表未就绪、配置缺失等原因。
- 主题绑定壁纸继续由原有联动机制处理。
- 不修改 Loader Runtime、Bootstrap、正式 Stable Core 或其他独立功能包。

## 验收重点
1. 保持角色 A 当前自选 UI 主题/预设，更新或重载 TLE，不应被 A 的默认配套方案覆盖。
2. 从 A 切换到 B，B 的默认方案仍自动应用。
3. B 没有默认方案时，切换进入 B 不改变当前配置。
4. 启用日夜定时后，同一时段内刷新不重复应用；跨越日夜边界后恢复当前时段方案。
5. 日夜时段内手动应用另一方案，刷新后仍保持手动方案，直到下一次时段边界。
6. API/模型不可用时仍应用其他可用项目，并逐项提示未应用原因。
