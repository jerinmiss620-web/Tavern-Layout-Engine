# TLE Core v0.3.211 — 主题同步位置和全局滚动条外观清理

## 快速切换分组管理 · 移动端
- 「当前 UI 主题」分类的「同步」按钮从分组标签行右侧，移动到下方搜索框的**左侧**。同步仍仅在主题分类显示，并调用原有 `importThemeManagerGroups()`，保留确认弹窗、分类隔离和数据处理。
- 分组筛选标签恢复占用整行，不再与「同步」竞争可见宽度，继续支持横向滚动。
- 将 `searchRow` 作为原有工具栏第一格：手机端占满工具栏首行、左侧同步按钮固定宽度，搜索输入框占剩余空间；其它分类不显示同步按钮，搜索框自然占满整行。
- 清除上版 `groupFiltersWrap` 节点和对应 CSS，不追加覆盖补丁；全局导入导出图标、其它操作按钮及列表滚动保持不变。

## TLE 滚动条样式统一检查与修复
- 扫描 Core 全部 CSS/动态源码，发现 **4 处 `scrollbar-width: thin`**，分别位于全局搜索结果、侧栏信息区、分组筛选条和分组批量操作条；全部直接从原规则删除。
- 删除 `#HotSwapWrapper .avatars_inline::-webkit-scrollbar { height: 4px; }`：不再用固定 4px 宽度强迫原生头像列表横向滚动条改变样式。
- Core 不再设置任何 `scrollbar-width`、`scrollbar-color`、`::-webkit-scrollbar` 或 `::-webkit-scrollbar-thumb` 外观规则；TLE 自己的全局搜索、分组管理、信息站列表、侧栏信息、楼层侠/最近聊天、诊断窗口和其它可滚动区因此可以接受宿主**全局**主题滚动条选择器控制，不和 TLE 自定义皮肤冲突。
- 保留原来的 `overflow`、`overscroll-behavior`、iOS 惯性滚动及两处宽工作区 `scrollbar-gutter: stable`；这些属性负责滚动行为与布局，不规定轨道、滑块或滚动条颜色。
- CSS 原理限制：滚动条伪元素外观**不会自动从父元素继承**；如果某第三方主题的 `::-webkit-scrollbar` 规则只匹配它指定的某个容器，并非全局选择器，则不能自动作用于其他 TLE 容器。本次不伪造主题滑块颜色，也不注入竞争性的 WebKit 规则。
