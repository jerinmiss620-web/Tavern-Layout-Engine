# v0.3.300 · 隐藏楼层身份匹配加固

基于 Mask Hero Test Core v0.3.299 继续开发；仅更新独立 `mask-hero-test` 测试通道，不修改正式版 Core v0.3.294，也不修改 Stable Loader / Bootstrap。

## 打码侠操作区

- 保留 v0.3.299 已完成的操作区顺序：「应用」「卸除」「保存」「删除」「应用范围」。
- 「应用范围」默认收起，展开/收起只改变面板可见状态，不改变已选择的范围；切换方案后恢复收起。
- 默认作用范围仍为全部楼层。

## 楼层隐藏保护

- 强化消息身份匹配：存在不同的非空 `gen_id` 时拒绝回退匹配，避免把新消息当作旧消息。
- 无稳定 `gen_id` 时，要求发送者、名称及可靠的时间/正文/相邻消息指纹共同支持唯一匹配；重复或信息不足时拒绝自动定位。
- 批量核验优先处理带稳定 `gen_id` 的记录，避免弱指纹记录抢占精确身份候选。
- TLE 执行「恢复隐藏」前先记录操作范围内原本隐藏的消息身份；执行后重新定位这些身份，只解除确实已恢复消息的备份，不再用旧楼层数字决定删除哪条保护记录。
- TLE 执行「隐藏」仍通过当前聊天的消息身份核验并同步新增备份；异常解除保护时仍只提示用户，不自动重新隐藏。
- 手动恢复继续只处理高置信度身份匹配，并通过酒馆原生隐藏命令执行；不唯一、身份冲突或消息位置变化时拒绝操作。

## 自动化验证

- 新增不同 `gen_id` 冲突、时间戳冲突、无 `gen_id` 编辑消息、重复时间戳歧义、稳定 ID 优先级及操作期间插入消息后的身份重定位测试。
- 保留 v0.3.299 的 IndexedDB 聊天隔离、非连续楼层恢复范围和禁止自动重隐藏回归。
- 自动化源码测试不等于 ST / TT 实机验收；仍需验证刷新、切换聊天、外部扩展隐藏/恢复、TLE 原生隐藏/恢复及长聊天场景。
