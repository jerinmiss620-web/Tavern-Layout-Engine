# v0.3.301 · 隐藏恢复按消息身份动态重定位

基于 Mask Hero Test Core v0.3.300 继续开发；仅更新独立 `mask-hero-test` 测试通道，不修改正式版 Core v0.3.294，也不修改 Stable Loader / Bootstrap。

## 楼层隐藏保护

- 手动恢复不再沿用最初核验时计算的楼层区间。
- 每次执行酒馆原生隐藏命令前，重新读取当前聊天，并按备份中的消息身份重新定位待恢复消息。
- 只对连续且完全由目标身份组成的楼层区间执行命令；目标消息之间若插入其他消息，自动拆成多个区间。
- 每执行一个区间后，再次读取聊天并核验目标身份确实恢复为隐藏状态；完成后才继续下一个区间。
- 目标消息身份缺失、重复、发生冲突或无法唯一匹配时立即停止，不使用旧楼层数字猜测目标。
- 已经重新处于隐藏状态的目标会从待执行队列中跳过，不重复执行命令。
- 保留 v0.3.300 的稳定 `gen_id` 优先、冲突拒绝、模糊匹配保护、TLE 原生隐藏/恢复备份同步，以及不自动重隐藏原则。

## 打码侠操作区

- 保留「应用」「卸除」「保存」「删除」「应用范围」的操作顺序。
- 「应用范围」默认收起；展开与收起不改变当前选定范围；默认范围仍为全部楼层。

## 自动化验证

- 新增消息插入后动态重算恢复范围、目标消息被其他消息隔开时拆分区间、分批恢复后重新计算下一段，以及身份缺失时安全中止的回归测试。
- 保留 v0.3.300 的 IndexedDB 聊天隔离、身份匹配、歧义拒绝、非连续范围与禁止自动重隐藏测试。
- GitHub Actions 自动回归通过后，仍需在 ST / TT 实机检查消息插入、删除、刷新、切换聊天和多段恢复。
