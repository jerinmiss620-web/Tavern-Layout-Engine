# v0.3.299 · 打码侠应用范围折叠与隐藏楼层保护

基于测试 Core v0.3.298 继续开发；仅更新独立 Mask Hero Test 通道，不修改正式版 v0.3.294。

## 打码侠操作区

- 将操作按钮顺序调整为「应用」「卸除」「保存」「删除」「应用范围」。
- 「应用范围」设置默认收起，点击按钮后才展开；再次点击收起。
- 默认作用范围仍为「全部楼层」；展开状态不写入方案，切换方案后恢复收起。
- 缩短原有「卸除效果」「保存方案」「删除方案」按钮文案，不改变其功能。

## 楼层隐藏保护

- 新增本机 IndexedDB 隐藏楼层备份，按角色 / 群聊及当前聊天文件身份隔离。
- 自动备份当前已隐藏楼层，并通过聊天加载事件及消息 DOM 的原生 is_system 状态变化进行核验。
- 消息身份优先使用 extra.gen_id；缺失时综合 send_date、name、is_user、正文内容哈希及前后相邻消息哈希进行匹配。
- 插入或删除楼层后按消息身份重新定位，不再仅依赖旧 mesid；匹配不唯一或可信度不足时拒绝自动定位。
- TLE 自己执行隐藏时同步备份；TLE 自己执行恢复时同步解除对应保护，避免把用户主动恢复误判为异常。
- 检测到其他脚本、扩展或刷新流程解除隐藏时，仅提示并提供「恢复隐藏」「接受当前状态」两个明确操作。
- **默认不自动重新隐藏。** 用户点击恢复后才调用酒馆原生 /hide；只恢复身份匹配可信的楼层。
- 备份只保存消息身份元数据和内容哈希，不保存正文副本；不写回原始聊天文件，不替代酒馆原生隐藏机制。

## 自动化验证与实机验收

- 新增回归测试：消息插入后的身份定位、gen_id 优先级、无 gen_id 的指纹回退、重复消息歧义拒绝、非连续楼层恢复范围及禁止自动重隐藏。
- 新增打码侠操作区顺序与默认折叠状态断言。
- 自动化通过不等于 ST / TT 实机验收；仍需在刷新、切换聊天、外部扩展隐藏 / 恢复、手动恢复和长聊天场景下测试。
