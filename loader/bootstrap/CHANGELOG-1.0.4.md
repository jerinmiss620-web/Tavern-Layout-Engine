# Permanent Bootstrap v1.0.4 — 2026-11-22

- 针对 Android 原版 SillyTavern 的 `Failed to fetch` 和 `signal is aborted without reason` 报告，统一首次获取 Loader 与更新检查的请求容错。TT 的迁移/偶发检查现象仍为独立的未确认问题。
- 每个清单/源码请求最多三次，失败后等待 500ms、1000ms；网络失败、自身 20 秒超时、未知来源中断及 HTTP 408/429/5xx 可重试，其他 HTTP 响应不重试。
- 以 Bootstrap 生命周期控制器、单次请求控制器和超时定时器实际状态区分取消来源；销毁、重新初始化、脚本/宿主页面卸载取消在途请求及等待，不误报超时、不弹最终失败诊断。
- 重试期间显示进度；成功后自然继续已存在的 Loader/Core 启动流程。全部失败后沿用 1.0.3 独立诊断弹窗，补充请求阶段、尝试次数、错误类型和原始原因，保留复制诊断。
- 重复检查共用在途 Promise，清单身份一致时复用已验证源码并重新验证；不重复下载相同 candidate/Last。检查失败不销毁现有健康版本、不清除持久缓存。
- 首次启动耗尽请求后不再每分钟循环；联网事件或手动检查可开启新一轮有限尝试。健康运行时保留六小时更新检查，已验证新版本遇到旧 Loader 忙碌仍保持原有及时恢复机制。
- 完整保留正式仓库来源、固定 Commit、SHA-256、UTF-8 字节数、Last Known Good、Previous 回滚及自动更新开关。Core 0.3.211、Loader Runtime 0.3.4 及其清单均不变。
- 新增独立 1.0.4 JS/JSON；1.0.3 已发布文件未覆盖，并归档原字节回归样本。旧 Bootstrap 需停用后手动导入并启用 1.0.4，再完整刷新宿主；不清理聊天或缓存。
- 扩展现有诊断、忙碌重试和完整源码更新链测试；自动化模拟通过不能代替 Android ST 与 iPhone TT 实机验收。没有增加 UA 特判或聊天事件触发器。
