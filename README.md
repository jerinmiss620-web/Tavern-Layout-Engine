## 一次安装，后续自动更新

正式发布：**Core v0.3.220 / Loader Runtime v0.3.6 / 固定 Bootstrap v1.0.6**。

1. 下载 [Bootstrap 安装包](loader/bootstrap/TLE-Permanent-Bootstrap-1.0.6.json)，在酒馆助手中导入一次。已安装旧 Bootstrap（包括 v1.0.3）的用户也需停用旧版并重新导入 v1.0.6 一次；以后 Core/Loader 依旧自动更新。
2. 首次迁移时禁用旧独立 Stable/Test Loader、旧 Bootstrap 和独立 Core，保留为禁用备份；启用 v1.0.6 并完整刷新酒馆／重新打开 TT。已有缓存和设置会继续使用。
3. 以后保留 Bootstrap 启用。Core 与 Loader 发布新版本只需更新 GitHub，无需重复导入、下载 Core JSON 或执行控制台命令。

更新链：`固定 Bootstrap → loader/latest.json → Loader Runtime → latest.json → Core`。

两个更新层共用默认开启的持久开关；启动、恢复联网和持续运行期间自动检查。关闭后仍显示更新提示，重新开启立即继续更新。TLE 面板的「版本与更新」使用默认收起的原生折叠区，显示实际运行版本、远程版本、绿色提醒、检查/安装按钮和结果。没有第二套 Loader 面板。

下载和缓存源码都验证固定仓库、来源路径、40 位 Commit、SHA-256 与 UTF-8 字节数；新版本启动并持久写入成功才算更新成功，失败自动恢复 Last Known Good / Previous。首次安装需要网络；已有可用缓存时可离线恢复。Bootstrap 自 v1.0.4 起提供有限重试；当前 v1.0.6 对清单和源码请求最多尝试三条线路，失败间隔为 250ms、500ms，仅自身定时器触发才认定超时；主动取消不重试，安全验证失败拒绝执行。首次临时失败恢复后自动继续 Loader/Core 启动，无需发送消息。沿用启动失败独立诊断弹窗，区分旧 Loader 冲突、Loader 未加载与 Core 未加载，并显示请求阶段、尝试次数、错误类型，支持复制诊断和刷新重试。此提示只在 Bootstrap 确实执行、能访问宿主 DOM、且启动失败时出现。浏览器清空站点数据后需要联网重新取得源码，仍不需要重新导入 Bootstrap。

## 第三方布局插件兼容性

TLE 接管原版 SillyTavern 与 TauriTavern 的顶栏及侧边导航布局，并负责主题层面的视觉兼容修复。若同时启用其他会改写顶栏、菜单或导航结构的第三方脚本（例如菜单精简器），可能发生布局管理权限冲突。请自行关闭第三方脚本中与 TLE 重叠的管理功能。TLE 不保证与第三方布局管理插件同时启用时的兼容性，也不负责修复其他脚本接管或改写布局后产生的问题。

## 界面所有权与主题继承原则

TLE 只为自己创建的界面定义必要的视觉样式，例如侧边导航、整理侠、独立弹窗和自有控件；这些样式优先使用酒馆当前主题提供的颜色与视觉变量。对于酒馆原生面板，TLE 只在确有需要时做局部布局或兼容性调整，不主动重绘整套视觉。

角色管理、世界书编辑等酒馆已有完整功能的界面继续使用原生系统，不另建一套重复管理器。角色头像预览区及其卡片外观由当前主题决定；TLE 不强制统一成自己的画廊或卡片样式，也不覆盖主题作者已经完成的设计。PC 与移动端可以采用不同的信息密度和布局，不机械照搬。

## 当前开发分支（未发布）

开发分支：`feature/organizer-nav-worldbooks-20261125`；工作源码：`development/organizer/TLE.js`（Core 候选版本标记 0.3.231）。

整理侠的资源管理现在直接位于自己的原生形态 `.drawer-content` 内，不再套用第二层 `.tle-search-surface`。抽屉图标、导航文字与全局搜索弹窗的跳转入口统一调用明确的开合控制器，直接维护 `openDrawer / closedDrawer`；打开时先关闭其他普通抽屉和 TLE 控制面板，移动端仍由原生导航生命周期收起侧栏。

本分支将全局搜索与整理侠拆分为两个独立功能：全局搜索恢复为工作区顶栏的独立按钮和居中弹窗，保留原有搜索能力；弹窗内提供「进入整理侠」跳转入口，但不承载资源管理。整理侠仍是侧边栏第十个一级功能抽屉，位于角色管理下方，拥有独立 `.drawer-content`、自己的资源筛选输入框、分组和批量管理功能，按 `openDrawer / closedDrawer` 展开收起。世界书采用统一清单，分别识别全局启用、角色主要绑定、额外绑定、未绑定和疑似孤儿，并提供「全部 / 已绑定 / 未绑定 / 疑似孤儿 / 全局启用」快速筛选；全局启用与角色绑定是可重叠的独立状态。懒加载角色卡仍支持按需扫描，扫描未完成时不把未知绑定误判为未绑定。本轮不实现新的首页画廊，也不改造酒馆原生角色预览区；首页画廊需求单独讨论。世界书分组使用名称作为稳定标识，并迁移旧索引键；批量删除仍调用酒馆原生接口，不另建世界书编辑器或角色管理系统。全局搜索与替换的后续整合留待 Codex 单独处理，不在本候选版本混入。

**PC 布局：** 整理侠在宽屏下采用三栏：左栏选择资源类型，中栏选择「全部项目 / 未分组 / 指定分组」，右栏显示当前资源列表、搜索、世界书状态筛选与批量操作。左侧分类、中间分组和右侧资源列表分别拥有独立滚动区域。**移动端布局：** 同一组 DOM 改为紧凑单栏工作区；同步、导入、导出三个工具按钮始终统一显示在标题右侧，移除重复关闭按钮；同步按钮始终可见，点击后读取主题管理已有分组，并仅更新 TLE 的 UI 主题分类；分类与分组筛选保留横向滑动，并使用常驻 3px 滚动指示条；目标分组与分组管理操作共用一行；批量操作采用紧凑三列布局，按钮高度 30px 且清除默认外边距，资源列表占据剩余高度。不另建移动端管理器，也不改变分组数据结构。

**孤儿识别边界：** 若角色卡删除后，唯一的主要世界书引用也随角色卡文件一并消失，酒馆没有留下可追溯关联，TLE 无法还原它原来绑定的角色；这类世界书会显示为「未绑定」，供人工核对。仍保留在酒馆额外绑定记录中的失效角色关联可标记为「疑似孤儿」。聊天级或身份级引用不属于本轮角色绑定判定范围。懒加载扫描仅在用户主动点击时执行，逐张读取角色元数据，可能增加当前会话内存占用。

### 首次加载提示与下载线路

Bootstrap v1.0.6 启动后立即显示「TLE 正在努力加载中，请稍候…」非阻塞提示；成功后自动消失，失败转交独立诊断弹窗。Loader/Core 均从 jsDelivr、Fastly jsDelivr、GitHub Raw 三线路获取受信任仓库文件；固定 Commit、SHA-256、UTF-8 字节数校验不变。更新检查在已有健康实例时先用短时间核对官方 GitHub Raw 清单，再回退 CDN；CDN @main 清单可能缓存旧内容，不保证绝对实时。旧 Bootstrap 必须一次性重新导入 v1.0.6，Loader/Core 后续自行更新。

### 首次启动提示及 WebKit 存储连接恢复（v1.0.6）

Bootstrap 启动即出现「TLE 正在努力加载中，请稍候…」，至少短暂可见约 1.2 秒；提示不影响运行速度，加载成功后自动消失。iOS TT 或 Android 宿主若发生 IndexedDB 连接失效，Bootstrap / Loader 有限重建连接一次，失败明确提示完全重启宿主。不清空或绕过缓存校验、版本保护与回滚。
